  • Termurah dan khusus OCR: qwen-vl-ocr. Taksiran sekitar Rp 4–8 per struk (±1.500–2.000 token gambar + ±500 token hasil).
  • Kalau yakin < 85% atau total tak cocok, ulangi otomatis dengan qwen3-vl-plus.
  • Belum diuji pada struk asli. Sebelum dibangun, adu 20 struk nyata (termal pudar, nota tulis tangan) antar model untuk memastikan akurasinya.

Pipeline

  • Ponsel kompres foto (sisi panjang ≤ 1600 px, JPEG) → unggah ke storage privat.
  • Endpoint baru di auth-server memanggil Helipod AI Gateway; kunci API hanya di server.
  • Prompt meminta JSON terstruktur: merchant, tanggal, total, pajak, item (nama, qty, harga), keyakinan per field.
  • Server memvalidasi: jumlah item = total, tanggal wajar, deteksi duplikat (merchant + total + waktu ±10 menit).
  • Hasil dikirim ke layar Periksa; kategori ditebak dari nama item + riwayat pengguna.

Penyimpanan

  • receipts: id, user_id, gambar (path storage), status (antre, membaca, siap, gagal), merchant, tanggal, total, pajak, keyakinan, json mentah, model.
  • receipt_items: nama, qty, harga, kategori, keyakinan.
  • Catatan keuangan menunjuk ke receipt_id sebagai lampiran.
  • RLS per pengguna; bucket privat; foto asli opsional dihapus (Pengaturan).
  • Saat ini data keuangan hanya di perangkat, jadi lampiran struk butuh sinkron Supabase lebih dulu atau disimpan lokal dulu (keputusan di bawah).

Keputusan yang saya butuhkan

  • Penyimpanan: langsung ke Supabase (butuh migrasi produksi) atau lokal dulu di perangkat?
  • Batas pakai: bebas, atau batasi mis. 30 struk/bulan gratis dan tak terbatas di Plus?
  • Simpan otomatis untuk struk yakin ≥ 95%: aktif bawaan atau pilihan pengguna?
  • Foto asli: simpan selamanya atau hapus setelah 90 hari?
