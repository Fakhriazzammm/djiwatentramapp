**Date:** 2026-05-15
**Author:** Hermes Agent
**Status:** Draft

---

## 1. Goal

Pisahkan satu Vite app (`apps/web`) menjadi **tiga** app terpisah dalam monorepo yang sama:

| App | Domain | Isi | PWA |
|---|---|---|---|
| **POS** | `kasir.djiwatentram.com` | POS Kasir (`/menu`) + Attendance + Booking + Karyawan profile | ✅ "Djiwa Tentram POS" |
| **Admin** | `admin.djiwatentram.com` | Admin dashboard (`/admin/*`) + Auth flow | ❌ No PWA (desktop) atau opsional |
| **Customer** | `order.djiwatentram.com` | Customer ordering (`/$brandSlug`) + Minigames | ✅ "Djiwa Tentram Order" |

Backend & database tetap **satu Supabase yang sama**.

---

## 2. Option A vs Option B — Perbandingan

| Aspek | **Option B** (2 App) | **Option A** (3 App) |
|---|---|---|
| **App count** | 2 | 3 |
| **Split point** | Internal (POS+Admin) vs Customer | POS vs Admin vs Customer |
| **Domain** | `app.djiwatentram.com` + `order.djiwatentram.com` | `kasir.djiwatentram.com` + `admin.djiwatentram.com` + `order.djiwatentram.com` |
| **Bundle size** | Menengah — Admin masih load POS code | **Maksimal** — tiap app cuma load kodenya sendiri |
| **Shared code** | 1 shared package | **1 shared package + lebih banyak per-app code** |
| **Auth model** | 2 pola (internal auth, public) | **3 pola** (karyawan PIN login, admin login, public) |
| **PWA** | 2 PWA | 2 PWA (POS + Customer), Admin desktop biasa |
| **Deploy targets** | 2 | 3 |
| **Kasir → Admin flow** | ✅ Satu domain, switch route aja | ❌ Beda domain, harus login ulang |
| **Isolasi** | Sedang | **Maksimal** — POS error gak ngaruh ke Admin |

## 5. Auth-Model Diff — 3 Pola Berbeda

### 5.1 POS App — Karyawan PIN + Admin Login

```
POS Auth Flow:
├── /login → Login dengan email/password (admin) 
├── /karyawan/login → Login dengan PIN (kasir)
└── Route guard:
    ├── /menu, /attendance, /booking, /home → butuh auth (PIN atau email)
    ├── /karyawan/$username → butuh auth
    └── /login, /karyawan/login → public
```

**Root layout (`__root.tsx`):**
- Sama seperti sekarang di `apps/web/src/routes/__root.tsx`
- TAPI hapus heuristic brandSlug (line 24-28)
- Public pages: `/login`, `/karyawan/login`
- Tetap pakai `YumiAuthProvider` + `useYumiAuth`
- Tetap pakai `AppDataProvider` + `CartProvider` (untuk `/menu`)

### 5.2 Admin App — Admin Login Only

```
Admin Auth Flow:
├── /login → Login dengan email/password (admin only)
├── /register → Register karyawan baru
└── Route guard:
    ├── /admin/* → butuh auth admin
    ├── /register → public (kalo enabled)
    └── /login → public
```

**Root layout (`__root.tsx`):**
- Mirip POS tapi **tanpa `/karyawan/login` di public list**
- Public pages: `/login`, `/register`, `/register/selesai/*`
- Tetap pakai `YumiAuthProvider`
- **TIDAK** pakai `CartProvider` — admin gak perlu cart
- Tetap pakai `AppDataProvider` (untuk site settings)

### 5.3 Customer App — Public (No Auth)

```
Customer Auth Flow:
├── /$brandSlug → public (tanpa login)
├── /$brandSlug/minigames → public
└── Route guard: TIDAK ADA
```

**Root layout (`__root.tsx`):**
```tsx
function RootContent() {
    return (
        <div className="min-h-app bg-background font-sans text-foreground antialiased">
            <Outlet />
        </div>
    );
}
```

**TIDAK ada:**
- ❌ YumiAuthProvider
- ❌ useYumiAuth
- ❌ AppDataProvider (setting dibaca langsung di component)
- ❌ CartProvider (cart state local di CustomerOrderingPage)
- ❌ useGlobalKeyboardNavigation
- ❌ useSiteBrandingMetadata
- ❌ Auth guard redirect

## 10. Risk & Tradeoffs

### 🔴 High Risk

| Risiko | Dampak | Mitigasi |
|---|---|---|
| **Auth duplication** | POS dan Admin punya login flow masing-masing — user admin harus login 2x kalau mau akses POS | Terima sebagai tradeoff, atau buat SSO |
| **`use-hybrid-write-actions.ts` (6084L) split** | File raksasa campur fungsi POS + Admin + Customer | Audit dulu sebelum split. Bisa jadi 3 file: shared-write, pos-write, admin-write |
| **Admin layout route.tsx (1281L)** | Sidebar admin punya link ke `/menu` (Line 1067: `to="/menu"`) | Link "/menu" di sidebar admin → ganti atau hapus |
| **Admin route.tsx navigation** | Ada `BOTTOM_NAV_ITEMS` yang mungkin include POS routes | Audit semua navigasi di admin |

### 🟡 Medium Risk

| Risiko | Dampak | Mitigasi |
|---|---|---|
| **Shared UI components** | Admin butuh SEMUA UI components (dropdown, tabs, select, dll) → shared package lebih besar | Opsi: tiap app punya copy UI sendiri, atau satu shared package UI |
| **Tailwind duplication** | 3 app → 3 Tailwind build | Turborepo cache — build sekali, reuse |
| **Env variables** | 3 app butuh env yang sama | Root `.env` atau masing-masing `.env` |
| **`main.tsx` duplication** | Provider tree beda per app | Sederhanakan per-app |

### 🟢 Low Risk

| Risiko | Dampak |
|---|---|
| **CSS collision** | Beda domain → beda scope CSS — aman |
| **PWA conflict** | Beda domain → no SW conflict |
| **Build cache** | Turborepo handles |
