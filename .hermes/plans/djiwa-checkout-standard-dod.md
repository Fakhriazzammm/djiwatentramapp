# Djiwa Checkout Standard — Definition of Done

- [ ] Shared checkout UI package exists with typed reusable components and one-surface card rules.
- [ ] Djiwa Pay confirmation step consumes shared header, payment method, summary, notice, and action components.
- [ ] Djiwa Pay and QRIS behavior remains unchanged: wallet balance gate, QRIS redirect, back action, and payment CTA.
- [ ] Customer app checkout remains behaviorally untouched; its existing layout is the visual reference.
- [ ] Shared package and Djiwa Pay typechecks pass.
- [ ] Djiwa Pay production build passes.
- [ ] Diff is whitespace-clean and only intended files are staged.
- [ ] Live Djiwa Pay HTTP response and deployed asset are verified after release.
- [ ] Visual preview evidence is captured or a deterministic DOM/CSS preview is recorded.
