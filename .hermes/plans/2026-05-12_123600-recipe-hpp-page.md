# Plan: Halaman `/admin/recipe/hpp` — HPP Terintegrasi Resep

## Goal

Buat halaman HPP (Harga Pokok Produksi) baru di `/admin/recipe/hpp` yang terintegrasi dengan data resep `/admin/recipe` dan mengambil harga bahan baku dari inventory (`/admin/inventory`) dan transaksi pengeluaran (`/admin/finance/transactions`).

---

## Current Context

### Existing HPP Calculator (`/admin/hpp-calculator`)
Sudah ada halaman HPP yang sangat komplit (2890 LOC di lazy component) dengan:
- Portfolio view (link semua produk → HPP status)
- Editor dengan ingredient/overhead rows + live metrics
- Margin analysis, price simulation
- AI cost suggestions dari transaksi
- Recipe sync (upsert dari resep)

**Tapi user minta halaman baru terpisah yang lebih fokus & terintegrasi dengan Resep** — jadi ini bukan *replace*, melainkan halaman baru yang lebih sederhana dan spesifik untuk *recipe costing*.

### Route Tree (TanStack Router — file-based)
| Path | File | Component |
|------|------|-----------|
| `/admin/recipe` | `recipe.tsx` | Outlet (parent) |
| `/admin/recipe/` | `recipe.index.tsx` | `RecipeStudioPage` |

### Data Sources
1. **pos_inventory** — tabel inventory: `_id`, `ingredientName`, `unit`, `quantity`, `latestReferencePrice`
2. **pos_inventory_latest_costs** — view SQL: `inventoryId`, `latestCostPerUnit`, `avgCostPerUnit`
3. **pos_recipes** — resep: `_id`, `productId`, `ingredients: [{inventoryId, amount}]`
4. **financialTransactions** (via `pos_expenses`) — data pengeluaran untuk fallback harga
5. **hppCalculations** — existing HPP calculations (bisa dijadikan referensi)

### Hooks yang Tersedia
- `useHybridInventory()` — daftar inventory
- `useHybridLatestInventoryCosts()` — map inventoryId → latestCostPerUnit
- `useHybridAllProducts()` — semua produk
- `useHybridRecipes()` — resep per produk
- `useHybridBaseRecipes()` — base recipe
- `triggerHybridRefresh()` — global refresh setelah write

## Proposed Approach

Buat halaman **`/admin/recipe/hpp`** dengan 2 bagian utama:

### Bagian 1: Selector Resep
- Dropdown/search untuk pilih produk (dari `useHybridAllProducts`)
- Otomatis load resep terkait (dari `useHybridRecipes`)
- Tampilkan daftar bahan baku dari resep dengan harga terbaru

### Bagian 2: Tabel Perhitungan HPP
Tabel dengan kolom-kolom:

| Kolom | Sumber |
|-------|--------|
| ✅ Bahan Baku (nama) | Dari resep → link ke inventory |
| ✅ Jumlah/Porsi | Dari resep (amount) |
| ✅ Satuan | Dari inventory (unit) |
| ✅ Harga Satuan | `pos_inventory_latest_costs.latestCostPerUnit` (atau 0 jika tidak ada) |
| ✅ Subtotal | Jumlah × Harga Satuan (komputasi otomatis) |
| ✅ Aksi | Tambah/Hapus baris (manual override) |
| ✅ **Total HPP per Porsi** | Komputasi otomatis (SUM subtotal) |

### Fitur Tambahan
- **Tambah bahan baku manual** — user bisa nambah baris baru pilih dari inventory dropdown
- **Override harga** — user bisa ubah harga satuan manual jika data kosong/tidak akurat
- **Ambil dari transaksi** — fallback: cari harga terbaru di financialTransactions untuk inventory item yang belum punya latestCost
- **Simpan perhitungan** — write ke tabel `hppCalculations` via `useHybridCreateHppCalculation` / `useHybridUpsertHppFromRecipe`

### CRUD Lengkap pada Tabel Bahan Baku

| Operasi | Cara | Detail |
|---------|------|--------|
| **Create (Tambah)** | Tombol `[+] Tambah Bahan` | Muncul dropdown pilih inventory → auto-fill nama, satuan, harga terakhir. Bisa tambah baris kosong → pilih nanti. Bisa tambah di baris mana saja (sisip di atas/bawah baris tertentu via tombol `⊕`). |
| **Read (Lihat)** | Tabel render | Setiap baris tampil: nama bahan, jumlah, satuan, harga/satuan, subtotal. Sumber harga ditandai badge (💾 Inventory / 📄 Transaksi / ✏️ Manual). |
| **Update (Edit)** | Inline edit langsung di sel | • **Edit bahan baku**: klik kolom nama → dropdown ganti ke inventory item berbeda (harga otomatis update).<br>• **Edit jumlah**: input number inline — subtotal & total real-time.<br>• **Edit satuan**: dropdown satuan (ml/gram/pcs dll).<br>• **Edit harga satuan**: input number — override harga otomatis, badge berubah ke ✏️ Manual.<br>• **Edit urutan baris**: drag-and-drop atau tombol ⬆⬇ untuk reorder. |
| **Delete (Hapus)** | Tombol `🗑️` per baris | Hapus baris + konfirmasi inline (undo 3 detik atau konfirmasi modal untuk yang sudah tersimpan). Bisa juga **hapus jumlah** (isi 0) — baris tetap ada tapi subtotal 0. |
| **Bulk actions** | Select checkbox beberapa baris | Hapus massal, reset harga ke default, copy dari resep lain. |

### Step 4: Implementasi CRUD Lengkap Tabel Bahan Baku

Setiap baris ingredient adalah object state dengan `id` unik (generateId).

**4a. CREATE — Tambah Baris**
- Tombol `[+] Tambah Bahan` di footer tabel → push `createEmptyIngredient()` ke array
- Tombol `⊕` di setiap baris → sisip baris baru setelah baris tersebut
- Dropdown pilih inventory → panggil `useHybridInventory()` → filter → set `ingredientName`, `inventoryId`, `purchaseUnit`, `conversionFactor`, `purchasePrice` dari `latestCostPerUnit` (jika ada)
- Bisa tambah baris kosong tanpa pilih inventory dulu

**4b. READ — Render Tabel**
- Map semua `ingredients[]` → baris tabel
- Setiap sel adalah **input/select editable** (bukan text biasa)
- Kolom: Bahan Baku (select), Jumlah (input number), Satuan (select), Harga Satuan (input number), Subtotal (auto computed), Aksi (tombol)
- Badge sumber harga: `💾` = dari inventory terbaru, `📄` = dari transaksi, `✏️` = diubah manual

**4c. UPDATE — Edit Inline Setiap Sel**
- **Edit bahan baku**: select/dropdown ganti inventory item → harga & satuan auto-update
- **Edit jumlah**: input `type="number"` min=0 → `setForm(prev => {...})` trigger recompute
- **Edit satuan**: dropdown unit (ml/gram/pcs/liter dll) → conversion factor auto-adjust
- **Edit harga satuan**: input number override → `purchasePrice` berubah, badge ke `✏️ Manual`
- **Reorder**: tombol ⬆ ⬇ di tiap baris → swap index array
- Real-time compute ulang setiap perubahan: `useMemo(() => computeHpp(form), [form.ingredients])`

**4d. DELETE — Hapus Baris**
- Tombol `🗑️` merah di setiap baris → filter splice dari array
- Konfirmasi: toast undo 3 detik untuk baris belum tersimpan
- Konfirmasi modal untuk baris yang sudah tersimpan di DB
- **Hapus jumlah** (isi 0) = baris tetap, kontribusi 0 ke total

**4e. BULK ACTIONS** (opsional, priority low)
- Checkbox select → tombol "Hapus Terpilih", "Reset Harga Terpilih"
- "Copy dari Resep Lain" — pilih produk lain → ambil ingredientnya

### Step 5: Simpan perhitungan

- Atau gunakan `useHybridUpsertHppFromRecipe` untuk sync dengan resep
- Tombol "Simpan HPP" → toast sukses

  - Tambah `"/admin/recipe/hpp"` ke `PAGE_TITLES` → `"HPP Resep"`

### B. Hooks Baru yang Mungkin Perlu Dibuat

**`useHybridTransactionCosts(inventoryId)`** — mengambil harga terbaru dari transaksi untuk inventory item tertentu:

```ts
// di use-hybrid-finance-analytics-data.ts atau baru
export function useHybridTransactionCosts(inventoryIds: string[]) {
  const [costs, setCosts] = useState<Record<string, number>>({});
  
  useEffect(() => {
    if (!inventoryIds.length) return;
    
    const supabase = createClient();
    // Fetch latest expense transactions for these inventory items
    const fetchCosts = async () => {
      const { data } = await supabase
        .from("financialTransactions")
        .select("inventoryId, amount, createdAt")
        .in("inventoryId", inventoryIds)
        .eq("type", "expense")
        .order("createdAt", { ascending: false });
      
      // Map: ambil transaksi terbaru per inventoryId
      const map: Record<string, number> = {};
      for (const row of data ?? []) {
        if (!map[row.inventoryId]) {
          map[row.inventoryId] = Number(row.amount);
        }
      }
      setCosts(map);
    };
    fetchCosts();
  }, [inventoryIds.join(",")]);
  
  return costs;
}
```

### C. Konvensi Backend yang Dipakai

1. **Semua data via Supabase Realtime / polling hooks** — tidak ada REST API terpisah
2. **Write actions via `use-hybrid-write-actions.ts`** — template: `useHybrid<Action><Entity>()` return async function
3. **Global refresh** — `triggerHybridRefresh()` setelah write agar hook lain re-fetch
4. **JSONB untuk ingredient array** — kolom `ingredients` dan `overheadCosts` di `hppCalculations` pakai JSONB
5. **ID pattern** — `_id: text` sebagai primary key, di-generate dari backend

### D. Keamanan Data (RLS)

Pastikan query Supabase yang ditambahkan comply dengan RLS policy:
- Row Level Security aktif di semua tabel
- Hanya user terautentikasi bisa read/write
- Filter `orgId` atau `siteId` sesuai konteks bisnis (jika ada)

- **Alternatif bahan**: "Kopi bubuk A habis. Alternatif: Kopi bubuk B (Rp 800/gr, -5% lebih murah)"

## UI/UX: Table-First Design

### Prinsip Utama: **Table = The Interface**

Tabel adalah komponen **pusat** halaman. Bukan sekadar tampilan data — tabel ini adalah **alat kerja** utama untuk mengelola HPP. Setiap operasi CRUD dilakukan **langsung di dalam tabel**, tanpa modal/dialog/popup terpisah.

### Layout Hierarchy

```
┌──────────────────────────────────────────────────────────────────┐
│  [HEADER BAR]                                                    │
│  [Product Selector]  [Batch Size]  [Simpan] [Portfolio] [🤖 AI]  │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ╔════════════════════════════════════════════════════════════╗  │
│  ║                    TABLE — 75% viewport                    ║  │
│  ║  ☐  Bahan Baku  │ Jml │ Sat │ Harga│ Sumber │ Subtotal│ ═ ║  │
│  ║  ───────────────────────────────────────────────────────── ║  │
│  ║  ☐  [Susu ▼]    │ 250  │ ml  │ 2,500│ 💾     │ 625     │ ═ ║  │
│  ║  ☐  [Gula ▼]    │  30  │ gr  │   200│ 💾     │  60     │ ═ ║  │
│  ║  ☐  [+] Tambah                                       ═ ║  │
│  ╚════════════════════════════════════════════════════════════╝  │
│                                                                   │
│  [SUMMARY BAR — sticky bottom of table]                          │
│  Total: Rp 685  │  Harga Jual: Rp 12,000  │  Margin: 94.3% ✅   │
│                                                                   │
│  [AI INSIGHTS PANEL — collapsible]                               │
├──────────────────────────────────────────────────────────────────┤
│  [FOOTER — sync status, etc.]                                    │
└──────────────────────────────────────────────────────────────────┘
```

### Table-First Design Rules

#### 1. Zero-Modal Editing
Semua operasi terjadi **inline** di sel tabel. Tidak ada dialog/popup/modal untuk CRUD biasa.

| Operasi | UX Pattern |
|---------|-----------|
| **Edit bahan** | Klik sel → dropdown inventory muncul **di dalam sel** (select inline) |
| **Edit jumlah** | Klik angka → jadi input number. `Tab` pindah sel. `Enter` confirm. `Esc` cancel |
| **Edit harga** | Klik harga → input number. Otomatis detect apakah override manual |
| **Tambah baris** | Baris kosong dengan `[+]` di footer tabel — langsung inline |
| **Hapus baris** | Ikon `✕` di ujung kanan — baris collapse dengan animasi |

#### 2. Spreadsheet-Like Navigation
- **Tab/Enter**: pindah ke sel berikutnya (kiri→kanan, atas→bawah)
- **Shift+Tab**: pindah ke sel sebelumnya
- **Arrow keys**: navigasi antar sel
- **Double-click**: edit mode untuk sel tertentu
- **Esc**: cancel edit, revert ke nilai sebelumnya
- Tanda `✎` di pojok sel yang bisa diedit

#### 3. Visual Affordances

| Elemen | Visual |
|--------|--------|
| **Sel diedit** | Border highlight biru (`ring-2 ring-blue-400`) |
| **Sel diubah manual** | Background kuning pucat (`bg-amber-50` — warning: berbeda dari default) |
| **Baris baru** | Background hijau transparan (`bg-emerald-50`, fade out 2 detik) |
| **Baris dihapus** | Slide right + fade out (300ms) |
| **Drag handle** | `⠿` di kiri baris (visible on hover) |
| **Checkbox** | Untuk bulk select |
| **Error** | Border merah (`border-red-400`) + tooltip "Jumlah tidak valid" |
| **Sumber harga** | Badge: 💾 (inventory), 📄 (transaksi), ✏️ (manual), 🤖 (AI suggest) |

#### 4. Sticky Elements
- **Header kolom tabel** — sticky top (tidak ikut scroll) — biar user selalu lihat nama kolom
- **Footer tabel** — sticky bottom (total + tombol aksi selalu terlihat)
- **Summary bar** — sticky di bawah tabel
- **Scroll**: hanya **body tabel** yang scroll, header + footer tetap

#### 5. Smart Defaults & Auto-Fill

Saat user **tambah baris baru**:
1. Baris kosong muncul dengan placeholder `[❓ Pilih Bahan]`
2. Dropdown inventory sudah filter: **tidak tampilkan bahan yang sudah ada** di baris lain
3. Setelah pilih bahan → auto-fill: nama, satuan, harga terakhir (dari inventory/transaksi)
4. Conversion factor auto-set berdasarkan satuan (kg→gr / L→ml / box→pcs)
5. Jumlah default ke `1` — user tinggal edit

Saat user **ganti bahan** di baris yang sudah ada:
1. Harga & satuan auto-update ke harga inventory terbaru
2. Jika sebelumnya manual override → tampilkan konfirmasi "Reset harga ke inventory?"
3. Tanda `✎` muncul di sel yang diubah manual

#### 6. Edge Case Handling di Tabel

| Skenario | UX |
|----------|----|
| **Harga kosong (0)** | Sel background merah samar + tooltip "Harga belum diisi. Klik ✨AI atau isi manual" + tombol ✨ di dalam sel |
| **Jumlah 0** | Baris tetap, kontribusi 0 ke subtotal. Text abu-abu. Tooltip "Isi jumlah > 0" |
| **Bahan duplikat** | Peringatan: "Susu Fresh sudah ada di baris 2" dengan tombol [Gabung] |
| **Data belum disimpan** | Indikator `•` merah di tab/title — "Ada perubahan yang belum disimpan" |
| **Conflict (data diubah dari luar)** | Banner "Harga {bahan} berubah sejak terakhir dibuka. [Review] [Abaikan]" |
| **Bahan di-resep dihapus dari inventory** | Baris tetap, tapi badge merah ⚠️ + tooltip "Bahan ini sudah tidak ada di inventory. Hapus atau ganti." |

## Risks & Tradeoffs

| Risk | Mitigation |
|------|------------|
| **Duplikasi dengan HPP Calculator yang sudah ada** | Halaman ini lebih fokus per-resep (satu produk → edit langsung). HPP Calculator adalah portfolio & bulk view. |
| **Data harga kosong** | Fallback ke manual input + tombol "Ambil dari Transaksi" |
| **Recipe belum ada** | Tampilkan pesan "Buat resep dulu" dengan link ke `/admin/recipe` |
| **Over-engineering** | Jaga sederhana — satu halaman, satu tabel, satu fungsi compute |
